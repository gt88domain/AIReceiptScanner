# Review Integration Test Plan

Status: superseded by `docs/plans/final-validation-plan.md`; not executed.

This document records the earlier `review/integration` checkpoint. It must not
be used to validate the final candidate because later, separately reviewed
topic branches expanded the approved scope.

## Scope

- Baseline: `ee550f5`
- Candidate: `review/integration`
- Excluded: `PAY-117`, `TOOL-107`, and all explicitly deferred CSV items.
- Preserved surfaces: Fumadocs, Orama, blog, and design-system gallery.

## Static and build gates

- Install from the committed lockfile with frozen mode.
- Run formatting, lint, type checks, and repository boundary checks.
- Build Web, server Worker, and optional native packages without deploying.
- Confirm active source has no imports from `archive/`.

## Authentication

- Verify Apple email is accepted only from verified identity-token claims.
- Verify deleted users lose phone data and cannot reuse a stale cached session.
- Verify production rejects missing Turnstile configuration for enabled public forms.
- Verify production rejects `BACKOFFICE_PREVIEW=1` before routing.
- Verify archived China-phone helpers are absent while legacy account display remains readable.

## Web, tooling, and i18n

- Verify locale parsing and safe `returnTo` behavior for email and social sign-in.
- Verify client environment injection exposes only the explicit allowlist.
- Verify dormant zh/jp catalogs are excluded from the launch bundle and can be restored.
- Verify production identity scanning includes the dormant catalogs.

## Storage and platform

- Verify JPEG, PNG, GIF87a, GIF89a, and WebP signatures; reject spoofed GIF prefixes.
- Verify executable stored content is served as an attachment with `nosniff`.
- Verify Aliyun OSS is not registered or configurable from active code.
- `STORE-105` status is partial: the five-minute cache change is included, but bounded global
  pagination is intentionally not implemented until ordering and cursor semantics are approved.

## Payments

- Verify active configuration accepts only Stripe for Web and RevenueCat for native.
- Verify historical Creem/Waffo billing rows remain readable but are not manageable.
- Verify a retired-provider pending webhook fails instead of being marked processed.
- Verify Stripe signature failures are 400 while missing server configuration remains retryable.
- Verify RevenueCat authorization comparison and retry semantics.
- Verify recovery checkout metadata matches each operation kind.
- Verify Web and iOS lifetime samples are `29900` cents.
- Before production rollout, inventory retired-provider pending webhook, operation, and outbox rows.

## Manual gates

- Confirm no deployed database contains unresolved Creem/Waffo operations before provider removal.
- Confirm no downstream deployment depends on Aliyun OSS URLs before provider removal.
- Review security headers in a browser only after the build gates pass.
- Do not merge to `main` until all approved checks pass and independent reviewers sign off.
