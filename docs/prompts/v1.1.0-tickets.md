## 产品定义（所有者已签字，不要重新讨论）

- Ticket = 一条带状态的联系/询盘记录 + 消息线程（类似邮件往来）。
- 三态：`open` → `replied` → `closed`。不做附件、不做分配/标签/SLA/优先级。
- Tickets 是**按需 capability 模块**：默认关闭，项目显式开启才有；普通项目用 Help 联系页（邮件）就够。
- 支持项目附加元数据：ticket 表一个 `metadata` JSON 列，项目自己解释，不做类型化自定义字段系统。
- 复用现有邮件设施做「管理员回复后通知用户」；预览模式下与既有预览阻断一致，绝不真实外发。

## 具体工作

### 1. Capability 接入

- 在 `packages/app-config/src/features.ts` / `profile-definitions.ts` 的**现有机制**中新增 `tickets` 旗标：四个官方 profile（full-saas / account-app / directory / directory-lite）**默认全部 false**；项目按需在自有配置中开启。
- `resolveBackofficeVisibility` 增加 `tickets` 派生项；侧边栏显隐统一走它。
- 预览环境（`BACKOFFICE_PREVIEW=1`）允许通过显式环境变量开启 tickets 用于验收，缺省关闭。

### 2. 数据模型（Drizzle，结构迁移与种子分离，遵守 `apps/server/src/db/README.md`）

- `ticket`：id、userId、subject、status(open/replied/closed)、metadata(JSON text, nullable)、createdAt、updatedAt、closedAt(nullable)。
- `ticketMessage`：id、ticketId、authorUserId、authorRole(user/admin)、body、createdAt。
- 索引：ticket(userId)、ticket(status)、ticketMessage(ticketId)。
- tickets 关闭时不得初始化相关资源；迁移本身按仓库规范执行。

### 3. 用户侧（仅 tickets 开启时显示）

- `Help` 分组下新增 `My Tickets`：列表（subject、状态、更新时间）、创建（subject + 首条消息）、详情页线程查看与回复。
- closed 的 ticket 只读，不允许用户再回复（重新提交请新建）。

### 4. 管理侧（仅 tickets 开启时显示）

- 新增 `Support` 页：ticket 列表（可按状态过滤）、详情线程、**回复**与**关闭**两个操作（这是本版本仅有的两个管理写操作）。
- 管理员回复后：ticket 状态 → `replied`，经现有邮件设施通知用户；预览模式阻断外发但状态流转正常。
- 管理员关闭：状态 → `closed`，写入 `closedAt`。
- 两个操作都必须经 `recordAdminAuditLog` 写审计。

### 5. Overview 待办队列

- v1.0 刻意未做的「开放 Ticket 数」卡片，现在补上：仅 tickets 开启时显示，计数 = status 为 open 的 ticket 数，深链 Support 页。

### 6. 安全边界（必须有测试）

- 用户只能读/写自己的 ticket（服务端校验 userId，不靠前端隐藏）：用户 A 读用户 B 的 ticket 必须 403/404。
- 管理端两个写操作必须过 admin 守卫；非管理员 403。
- 消息渲染防 XSS：禁止 `dangerouslySetInnerHTML`，纯文本渲染。
- 创建 ticket 限流（复用现有 rate limit 设施）。
- metadata 列不在用户侧回显为 HTML。
