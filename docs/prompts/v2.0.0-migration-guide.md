# v2.0.0 执行 Prompt：模版收官——《旧项目迁移指南》与文档定稿

> 用法：整段交给执行编码的 AI。前置：v1.2 已合并发布（main ≥ v0.11.0）。
> 本版本是纯文档版本，不改运行时代码。在独立分支实施，完成后停在未提交状态。

## 目标

模版机制全部就位（IA、Tickets、Apps/Modules 扩展点、预览工作流）。
本版本产出让下游项目能自助完成采用的文档。随后冻结未计划的模版功能开发；安全修复、上游维护与下游采用仍照常进行。

## 交付物

### 1. `docs/migration-guide.md`（核心交付）

面向「把旧项目（EasyStarter v0.4.0 时代）迁到当前模版」的完整指南，必须包含：

- **适用性检查**：项目当前基线、启用的 capabilities、旧后台有什么功能必须保留。
- **基线迁移路径**：in-place 升级 vs 新模版重建 + 搬运产品模块，两条路线的判断标准
  （上游差异数量、MOD manifest 数量、产品代码占比）。
- **后台功能映射表**：
  - 旧通用管理页 → 新 Admin 常驻五页（Overview / Analytics / Users / Audit / System），以及按 capability 显示的 Payments / Support
  - 旧业务管理页 → 管理模块（`createAdminModuleRoute()` + `modules/<domain>/backoffice.ts`）
  - 旧询盘/联系类功能 → Tickets（metadata JSON 承载业务字段）或 Help 联系页
  - 用户侧旧账户页 → Account 分组；旧订单页 → Purchases
- **能力开关清单**：billing / credits / creditPurchases / tickets / storage / jobs 各自的开启条件与显隐效果。
- **数据迁移规范**：沿用 `apps/server/src/db/README.md`——结构迁移、数据迁移、种子、回填、修复分离；每片必须有 owner、验证方法、回退方案。
- **治理衔接**：`.template/source.json` 基线更新、受保护差异登记（MOD manifest）流程。
- **验收清单**：预览环境人工验收步骤（复用 `pnpm preview:backoffice`）。

### 2. 文档收口

- 更新 `docs/backoffice-ia.md`：把 v0.9 → v1.2 的所有已定决策汇总为最终版（IA、显隐矩阵、永久不做清单）。
- 更新 `AGENTS.md` 或 `docs/` 索引中的后台相关引用，指向新文档。
- 记录当前已跟踪的基础执行包状态；未跟踪的下游采用 prompt 只作为审计输入，不改写、不纳入本次提交。
