# v1.2.0 执行 Prompt：Apps / Modules 编译期扩展点

> 用法：整段交给执行编码的 AI。前置：v1.1.0 已验收合并。
> 本版本在独立分支实施，完成后**停在未提交状态**，输出自检报告等审查。
> 本版本是「用上游后台替换旧项目后台」的关键机制：下游**只新增文件、不编辑任何上游已有文件**就能注册专有功能。

## 产品定义（所有者已签字，不要重新讨论）

- 路线 A：**编译期模块注册**。不做运行时插件、不做远程加载、不做沙箱——下游项目和模版是同一个代码库，模块就是受信任的本仓库代码。
- 两个对称扩展点：
  - **用户侧 Apps**：项目注册给最终用户的产品功能入口（如 URLs 的 submit、订单类 orders）。
  - **管理侧 Modules**：项目注册专有管理页（如 AIBranding 的 Domains）。
- 显隐：用户侧 `Apps` 分组仅在有 ≥1 个已注册模块时出现；管理侧模块入口同样按注册显隐。
- 本版本只做**模版侧的机制 + 约定 + 测试 + 文档**。AIBranding Domains 试点是下游工作，不在本 prompt 内。
- Purchases / Billing / Credits 等通用页面维持现状，不因扩展点改动。

## 具体工作

### 1. 模块声明约定（typed manifest）

- 约定：下游在 `apps/web/src/modules/<domain>/` 放置模块，其中 `backoffice.ts` 导出一个类型化 manifest，例如：
  ```ts
  export const backoffice: BackofficeModule = {
    id: "urls-submit",                                            // 全局限重，排序依据
    userApp: { titleKey: "...", routeId: "..." },                 // 可选
    adminModule: { titleKey: "...", routeId: "..." },             // 可选
    requiresFeature?: "billing" | "credits" | "tickets",          // 可选，限现有 features 旗标
  };
  ```
- 类型定义放 `apps/web/src/modules/types.ts`，字段保持最小：模块 id、导航文案 i18n key、路由标识、可选 feature 条件。
- manifest 只负责**导航收编与显隐**，不负责路由注册（见第 2 条）。

### 2. 注册：约定式自动发现（不编辑任何上游文件）

- 模版侧用 Vite `import.meta.glob` 扫描 `apps/web/src/modules/*/backoffice.ts` 完成发现；**上游仓库 `modules/` 下没有任何模块，发现结果为空**。
- 下游接入 = 新增 `modules/<domain>/` 目录；**禁止要求下游编辑上游已有文件**（不存在 registry.ts 这类汇集文件）。
- 发现结果按模块 `id` 排序，保证渲染稳定；重复 `id` 在 contract test 中报错。
- TanStack 文件路由约束：模块页面必须在 `apps/web/src/routes/` 下有对应**薄路由文件**（re-export 模块组件）。下游是**新增**该文件，属于增量添加而非修改核心；路由文件本身不进 `modules/`，在文档中写明这一分工。

### 3. 管理模块守卫：结构性保证

- 模版提供统一 helper `createAdminModuleRoute()`（封装 `createFileRoute`，内部固定 `beforeLoad: requireAdminRouteAccess`）。**管理模块的薄路由文件必须通过它创建**，从结构上保证守卫存在。
- 用仓库既有边界检查机制（`template-kit/repository-facts.json` / `check:boundaries`）登记规则：`routes/` 下管理模块薄路由文件禁止直接调用裸 `createFileRoute` 创建 admin 路径路由；新增规则按既有登记流程走。
- 不做源码文本扫描之类的脆弱检查。

### 4. Contract tests（本版本最重要的交付）

- 测试夹具里注册一个示例模块，断言：
  - 注册后用户侧 Apps 分组出现且仅出现注册的条目；未发现任何模块时（上游默认）导航与 v1.1 完全一致（防回归）。
  - 声明了 `requiresFeature` 的模块在该 feature 关闭时不出现。
  - `createAdminModuleRoute()` 创建的路由对非管理员拒绝访问（403/重定向）。
  - 模块 `id` 重复时报错。
- 测试模块只存在于测试夹具，不进入生产渲染路径。

### 5. 文档

- 新增 `docs/backoffice-modules.md`：下游新增专有模块的完整步骤（新增 `modules/<domain>/backoffice.ts`、新增薄路由文件、用户模块用普通 route、管理模块必须用 `createAdminModuleRoute`、i18n、测试要求），附最小示例。
- 更新 `docs/backoffice-ia.md` 显隐矩阵：Apps / Modules = 注册后出现。

## 明确不做（Non-goals）

- 不做运行时插件、远程加载、热插拔、沙箱。
- 不做 registry.ts 等需要下游编辑的上游汇集文件。
- 不做服务端 router 的动态注册（服务端模块沿用现有 `apps/server/src/modules/` 约定与 oRPC 组合方式，文档说明即可）。
- 不把任何真实项目功能（Domains、pay2submit）做进上游。
- 不改 v1.0 / v1.1 已定稿页面的行为。
- 不动 Central 与下游仓库。

## 测试与门槛

- `pnpm check:boundaries` 等 template 检查全绿；新增边界规则按 `template-kit/repository-facts.json` 既有流程登记。
