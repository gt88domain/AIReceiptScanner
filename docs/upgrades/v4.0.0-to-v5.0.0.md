# Upgrade from v4.0.0 to v5.0.0

v5.0.0 makes payment price selection explicit and hardens billing and operational audit behavior.
Adopt it on a dedicated branch and validate payment provider sandboxes before production rollout.

## Breaking configuration change

Only products that enable Billing or Credits need `PAYMENTS_PRICE_ENV`: set it to `test` for local and
staging environments that use test provider prices, and `prod` in production. For those products, the
server refuses to start when the value is missing or invalid, and rejects `test` when
`NODE_ENV=production`. Profiles with Billing and Credits disabled do not need this variable.

## Behavioral changes

- Subscription trial history is checked across Stripe and RevenueCat for the same user.
- Successful Stripe lifetime purchases must match the configured plan, price, amount, and currency.
- Webhook inbox rows remain durable idempotency and audit records; v5 does not delete processed or
  dead-letter rows automatically.
- Admin Jobs exposes a read-only, cursor-paginated event history for a specific job. The `job_event`
  table remains in place; no destructive migration is included.
- The full runtime router is checked against the stable platform contract without changing disabled
  module omission or 404 behavior.

## Adoption checklist

1. When Billing or Credits is enabled, add `PAYMENTS_PRICE_ENV` to the Server Worker environment.
2. For those products, confirm production uses `NODE_ENV=production` together with
   `PAYMENTS_PRICE_ENV=prod`.
3. Verify catalog amounts and currencies match Stripe lifetime prices exactly.
4. Confirm Stripe and RevenueCat identities map to the same internal user before relying on the
   cross-provider trial rule.
5. Keep the daily `10 16 * * *` trigger when Credits are enabled so credit maintenance runs.
6. Exercise checkout, lifetime purchase, webhook replay, dead-letter, and admin job-history flows in
   staging.

## Rollback

Re-deploy the last v4 commit and restore its environment configuration if startup or checkout fails.
This release has no database migration. The explicit price-environment variable can be removed again
only after the v4 code is restored.
