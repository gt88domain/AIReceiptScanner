# Upgrade from v0.4.3 to v0.4.4

v0.4.4 makes Storage and Email composable runtime capabilities. It does not
alter database schema, migrations, existing tables, Cloudflare resources, or any
downstream repository automatically.

Adopt on a dedicated branch. First copy the upstream changes, then move product
metadata and capability choices to `packages/app-config/src/product-config.ts`.
Keep `appConfig`, `resolveCommonConfig()`, and `resolveProductFeatures()` imports:
they remain compatible.

For a no-storage product, set Storage false and manually remove its R2 binding
from that product's Wrangler configuration. For no-email, set `enabled: false`,
`provider: "none"`, and all email capabilities false; manually remove Resend
secrets and hide public Email switches. Do not run migrations, delete historic
tables, create cloud resources, or hand-edit generated route files.

Run `pnpm check:wrangler-types`, `pnpm test:template`, and the normal build
before opening a Draft adoption PR. Wrangler type checks validate configuration
only and never deploy.
