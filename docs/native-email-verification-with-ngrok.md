# Native email verification with ngrok

Use a public HTTPS tunnel when a real device must open a verification link
generated by the local API Worker. On a phone, `localhost:3001` points to the
phone, not the development machine.

## Before starting

Adopt one native scheme and keep these sources aligned:

- `productConfig.common.app.nativeScheme` in
  `packages/app-config/src/product-config.ts`
- `expo.scheme` in `optional/mobile/app.json`

The template values are placeholders and may intentionally differ before
adoption. The mobile callback path comes from
`appConfig.native.routes.authSignIn` and is currently `/callback`, so the
resulting deep link has the shape `<native-scheme>:///callback`.

Use a development build for the end-to-end callback. Expo Go does not install
the product's custom scheme as the standalone app handler.

## Local flow

1. Start the API Worker:

   ```bash
   pnpm dev:server
   ```

2. Expose port 3001 with ngrok and copy its HTTPS forwarding URL:

   ```bash
   ngrok http 3001
   ```

3. Set the same public API origin in the Server and mobile development files:

   ```env
   # apps/server/.dev.vars
   SERVER_URL=https://<your-ngrok-host>

   # optional/mobile/.env.development.local
   EXPO_PUBLIC_SERVER_API_URL=https://<your-ngrok-host>
   ```

4. Restart the Server and build/install the mobile app:

   ```bash
   pnpm --dir optional --filter mobile run ios
   # or
   pnpm --dir optional --filter mobile run android
   ```

5. Sign up with a new address, open the verification email, and confirm the
   browser reaches the ngrok URL and returns to
   `<native-scheme>:///callback`.

Email verification proves mailbox ownership but does not automatically create
a session. After returning to the app, the user signs in normally.

## Troubleshooting

- Email still contains localhost: restart `pnpm dev:server` after changing
  `apps/server/.dev.vars`.
- Mobile still calls localhost: restart Expo or rebuild after changing
  `.env.development.local`.
- The callback does not open the app: confirm the product-config and `app.json`
  schemes match, then rebuild the development client.
- The ngrok host changed: update both environment files and restart both
  processes.
- Verification succeeds but the app is anonymous: this is expected; sign in
  after verification.

Relevant implementation paths are `apps/server/src/lib/auth.ts`,
`optional/mobile/lib/auth/auth.client.ts`,
`optional/mobile/configs/app-config.ts`, and
`optional/mobile/app/(auth)/callback.tsx`.
