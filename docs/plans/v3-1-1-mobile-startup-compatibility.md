# v3.1.1 startup compatibility plan

## Core goal

Ship a patch release that removes three template-owned false-start failures:

1. Wrangler binding freshness checks use the same production config and
   interface arguments as binding generation.
2. The isolated optional Mobile workspace declares every package it imports.
3. Better Auth's Expo client receives a SecureStore-safe, stable prefix rather
   than the human-readable application name.

## Observable acceptance criteria

- A freshly generated `apps/server/worker-configuration.d.ts` is accepted by
  the repository freshness checker without changing the generation contract,
  and formatting checks leave the generated bytes untouched.
- A fresh `pnpm --dir optional install` resolves `clsx` from the Mobile
  workspace's direct dependencies.
- The default Mobile auth storage keys contain only letters, numbers, `.`, `-`,
  and `_`, even when the display name contains spaces.
- Display names remain human-readable and downstream products do not need to
  patch template-owned Mobile infrastructure.
- Release Please produces patch version `v3.1.1`; no Cloudflare deployment is
  part of this change.

## Implementation phases

### Phase 1 — Wrangler freshness contract

- Owners: `scripts/check-wrangler-types.mjs`,
  `apps/server/worker-configuration.d.ts`, and `apps/server/.oxfmtrc.json`.
- Pass the production Wrangler config and `CloudflareBindings` interface to
  the `--check` invocation, matching `apps/server/package.json`.
- Regenerate the committed declarations with that contract and exclude the
  generated output from source formatting.

### Phase 2 — Optional Mobile dependency and storage identity

- Owners: `optional/mobile/package.json`, `optional/pnpm-lock.yaml`, and
  `optional/mobile/configs/app-config.ts`.
- Declare `clsx` in the isolated Mobile workspace.
- Use the product-owned native scheme as the auth/SecureStore prefix while
  keeping the display name for UI labels.
- Do not change downstream products or introduce a second configuration
  system.

### Phase 3 — Core-goal review

- Review the complete diff for scope, optional-workspace isolation, stable
  storage identity, and release compatibility.
- Confirm no release accounting files or deployment configuration changed.
