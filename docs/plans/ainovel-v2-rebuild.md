# AINovel v2 重建计划

## 一句话目标

用 EasyStarter 的新模板重建 AINovel 的统一入口：读者在网页发现、阅读和讨论作品，会员在网页管理权益并下载创作器；创作、生成、私有草稿和本地编辑由 macOS 桌面应用承担。旧项目保留为页面、路由、视觉和已有公开数据的参考，不把旧模板原样升级。

## 已确认的产品决定

- 主站继续使用 `ainovel.com`；全部旧 URL 尽量保全。
- 旧站视觉、信息结构和操作习惯延续，不做一次风格重设计。
- 网页是阅读、世界观、论坛、会员和 macOS 应用下载入口；创作器不嵌入网页。
- 网页与 macOS 应用共用账号和会员身份；草稿本地优先，可选云同步。
- 公开发布必须审核；论坛允许发帖/评论但不做私信，并采用自动过滤加人工审核。
- 会员和赞助以桌面端创作额度、模型能力和身份权益为主；在真实价格和权益接口完成前不启用收款。

## 当前进度

- 已完成：新模板项目、AINovel 品牌配置、旧站公开阅读/世界观/论坛/公告/静态页路由、图片资源、SEO 与旧 URL 跳转已进入新的 `novels` 模块。
- 已完成：会员支付、积分、后台、邮件和模板营销功能在新站默认配置中关闭，避免出现无效的模板入口。
- 尚未启用：生产 D1 绑定、域名、部署、真实会员支付和 macOS 应用接口。
- 下一小步：以本地或克隆 D1 运行公开阅读页；论坛发帖/评论需要单独的账户关联、审核与数据表设计，不能复用旧的只读论坛摘要表硬做。

## 这次保留什么

第一阶段先交付读者核心，并保留所有已有公共内容面：

1. 首页：明确 AINovel 是什么，展示推荐、热门和分类入口。
2. 小说库：搜索、分类、标签和一个简单排序；不做复杂筛选器。
3. 小说详情：封面、简介、标签、章节列表、相关推荐。
4. 章节阅读：干净的阅读版式、上一章/下一章、回到书籍。
5. 世界观、排行榜、论坛与公告：保留已有公开页面和 URL；论坛发帖/评论作为后续独立小功能。
6. 桌面创作器入口：在网页提供下载、账号和会员入口；不在网页重复做编辑器。
7. 基础 SEO：尽量保全全部旧 URL、标题描述、canonical、robots、sitemap 和永久跳转。
8. 延续旧站视觉、页面结构和熟悉操作，同时修复响应式与性能问题。

## 这次不做什么

以下功能不从旧项目搬过来，也不启用新模板的默认功能：

- 网页端小说创作器、生成器或私有草稿编辑器。
- Windows、iOS、Android 客户端。
- 私信、实时聊天、复杂推荐、自动化运营和复杂后台。
- 未确认的支付价格、支付密钥、桌面端权益接口或生产数据库改动。

以后确实需要时，再以独立小功能添加。第一版没有账号和写入操作，因此不需要为了“以后可能会用”而接入这些能力。

## 数据策略

继续使用现有 D1 中已经存在的公开小说、章节、世界观和论坛公开投影；不在这次重建中导入用户、支付或桌面应用的私有数据。

新站第一阶段只有查询：小说列表、详情和章节内容。开发先用本地样例或 D1 副本验证；上线前再确认现有 D1 的表、字段、索引和实际条数。由于 D1 绑定本身可以写入，新站在阅读版完成前不连生产 D1，也不保留任何写入接口。

已知要读取的公开表为 `novel_novels`、`novel_chapters`、`novel_worlds` 与 `novel_forum_threads`。桌面端私有草稿与生成记录不进入网站数据库；作品审核通过后才成为公开站可读的数据。

## 实施方式

不复制旧项目的 `custom` 目录，也不试图把旧模板升级到新模板。新项目从当前 EasyStarter 基线开始，只新增一个 `novels` 产品模块：

```txt
apps/server/src/modules/novels/  # 小说、世界观和论坛的受限公开读取 API
apps/web/src/modules/novels/     # 保留旧站视觉的阅读与社区页面
apps/web/src/routes/             # 很薄的 URL 路由和旧链接跳转
```

先完成可用的读者页面，再删除或关闭新模板中没有使用的菜单、路由和运行时能力。删除应当以“已无引用、不会影响阅读站”为准，而不是为了把模板文件数量清零。

## 分四步完成

### 1. 干净底座

- 将名称、站点文案、图标和公开导航换成 AINovel。
- 关闭默认 SaaS 导航，保留一个最小公共外壳。
- 建立本地的公开小说样例；不配置域名、密钥、支付或生产 D1。

完成标准：首页可打开，页面不出现模板品牌或登录/定价入口。

### 2. 阅读核心

- 实现小说列表、搜索和分类。
- 实现详情页和章节阅读页。
- 用旧站的公开小说内容校对字段与阅读体验，但重新写代码和界面。

完成标准：一名访客可从首页找到小说、打开详情、连续阅读章节并返回列表。

### 3. 全部公开面与收尾

- 添加世界观、排行榜、论坛、公告、静态页、空结果与 404 页面。
- 补齐 SEO、sitemap、robots 和全部旧 URL 的明确去向。
- 清理没有用到的模板营销页面和导航入口；保留账号基础，为桌面应用统一登录做准备。

完成标准：核心 URL 没有重复内容，搜索引擎只看到规范的公开阅读页。

### 4. 桌面端和会员接入

- 统一网站与 macOS 应用的账号；网站负责下载与会员入口。
- 应用本地优先，可选云同步；网页只展示经审核发布的公开作品。
- 完成桌面端权益 API、真实价格和支付配置后，才启用会员与生成额度。

完成标准：创作器与网页共用用户 ID 和会员状态，私有草稿不会泄漏到公开站。

### 5. 安全发布

- 用独立的预览 Worker 验收，不绑定 `ainovel.com`。
- 核对所有公共页面、SEO、移动端和现有 D1 的只读查询。
- 得到明确授权后才把生产 D1 绑定到新站，并最后切换域名。

完成标准：切换前能随时回到旧站；数据库没有被新站写入或改结构。

## 验收清单

- 手机和桌面都能顺畅阅读一部小说的多个章节。
- 首页、小说库、分类、详情、章节、世界观、论坛和公告页都可直接访问。
- 无模板品牌入口；桌面应用下载入口清晰。
- 没有连接生产数据库、部署或域名修改，除非另行授权。
- 切域名前才检查旧路径、canonical、sitemap、404 和回滚路径。

## 后续功能的判断标准

优先级为：阅读体验 → 内容发现与社区 → macOS 创作器 → 账号统一 → 会员和赞助。每次只做其中一个小项；不要让桌面端功能阻塞网页阅读体验。
